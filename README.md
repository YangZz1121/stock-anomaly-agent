# 个股异动研究 Agent

一个把"这只股票今天为什么跌"变成**可验证研究过程**的 Web 产品。

输入一句自然语言提问，产品输出一份结构化的研究 Brief，回答三个问题：

1. **发生了什么** —— 用统一口径把价格变化量化，并与行业、市场对比；
2. **为什么发生** —— 检索证据、生成候选驱动因素，再逐条做时间 / 横截面 / 特异性 / 机制四项验证；
3. **这些原因对公司意味着什么** —— 确认公司业务暴露、构建传导链，给出影响方向 × 影响期限 × 证据强度。

最后还有第四块：**当前仍未解决的问题**。产品把"不知道"当成研究结果的一部分输出，而不是当成失败掩盖掉。

## 一、启动方式

### 本地运行

需要 Python 3.9+。不需要 Node、不需要数据库、不需要任何密钥。

```bash
git clone <仓库地址>
cd stock-anomaly-agent

python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

uvicorn app.main:app --port 8000
```

打开 http://127.0.0.1:8000 即可使用。

不配置任何密钥时，产品会自动运行在**构造数据集**上，页面顶部会显示降级横幅。
主链路、故障演练、合规护栏全部可用，只是数据不是真实行情。

### 运行测试

```bash
pytest -q          # 138 项，全部离线，无需网络和密钥
```

### 数据源自检

配好密钥之后先跑这个，逐条确认哪个数据源真的通了，
以及产品这次到底走的是真实接口还是降级到了构造数据集：

```bash
python scripts/check_providers.py
```

它只打印调用结果和实际命中的 source，**不打印任何密钥内容**。

### Docker

```bash
docker build -t stock-anomaly-agent .
docker run -p 7860:7860 stock-anomaly-agent
```

### 部署到 Render

仓库根目录的 `render.yaml` 是 Blueprint 配置：Docker 运行时、免费档、
新加坡节点、健康检查指向 `/api/health`。

1. 把仓库推到 GitHub；
2. Render 控制台 → **New → Blueprint** → 选中该仓库 → Apply；
3. 需要真实数据源时，在 Service 的 **Environment** 里填写
   `FUYAO_API_KEY` / `IFIND_MCP_URL` / `IFIND_API_KEY` / `LLM_API_KEY`。

`render.yaml` 里这些键全部标了 `sync: false`，意思是"在控制台单独填写，不进仓库"，
所以仓库和镜像里都不存在任何密钥。一个都不填时服务会运行在构造数据集上，
并在页面顶部如实声明降级状态。

服务通过 `PORT` 环境变量绑定端口（Render 默认 `10000`），`Dockerfile` 的
启动命令已经读这个变量，因此本地、Render、其他容器平台用的是同一个镜像。

**免费档的两个特性需要知道**：无访问 15 分钟后容器会休眠，下次请求唤醒约需 1 分钟；
免费档没有持久磁盘，行业映射缓存每次冷启动都会重建
（所以 `render.yaml` 把 `INDUSTRY_MAP_MAX_CALLS` 压到了 40，避免冷启动打满接口频率限制）。

### 关于 Hugging Face Spaces

最初的部署目标是 HF Spaces，后来放弃了。原因记录在此，避免以后重复踩：
HF 现在**只有 Static Space 免费**，Gradio 和 Docker Space 都需要 PRO 账号。
而 Static Space 没有服务端运行时，跑不了 FastAPI；它的 secrets 还是通过
`window.huggingface.variables` 暴露给客户端 JavaScript 的，用来放 API Key 本身就不合规。

## 二、环境变量

全部可选。三个 Provider 默认都是 `auto`：**有密钥就用真实数据源，没有就降级到构造数据集**，
并在接口 `/api/config` 和页面横幅上如实声明当前状态。完整模板见 `.env.example`。

| 变量 | 作用 | 不配置时 |
| --- | --- | --- |
| `FUYAO_API_KEY` | 扶摇金融数据 API（行情、指数、成分股） | 使用 `fixtures/market/` 构造行情 |
| `FUYAO_BASE_URL` | 扶摇服务地址 | `https://fuyao.aicubes.cn` |
| `IFIND_MCP_URL` / `IFIND_API_KEY` | iFinD MCP（资讯、公告、研报） | 使用 `fixtures/evidence/` 构造证据 |
| `LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL` | 第二、三阶段的语义推理 | 使用内置确定性启发式推理层 |
| `MARKET_PROVIDER` / `EVIDENCE_PROVIDER` / `LLM_PROVIDER` | 强制指定数据源（`auto`/`fuyao`/`ifind`/`openai`/`mock`） | `auto` |

阈值类参数（单日集中度、方向一致性、路径效率、背离阈值、证据扩展窗口天数等）
同样可以用环境变量覆盖，默认值集中在 `app/config.py`，并且每一项都在代码里写明了选择理由。

**密钥管理**：`.env` 已列入 `.gitignore`；线上部署使用 Hugging Face Space Secrets 注入，
仓库内不存在任何密钥文件。研究轨迹在写入前会统一脱敏（`app/trace.py` 的 `_scrub`），
任何含 key / token / secret / authorization / password 的参数都不会出现在页面或日志里。

## 三、产品选择：为什么做这个

大多数"AI 炒股"产品的失败模式是同一个：**它给你一个结论，但你没法验证它**。
模型说"受政策影响下跌"，你无法知道它指的是哪条政策、政策什么时候发布的、
公司到底有没有相关业务、以及这个说法有没有被反向证据挑战过。

这个产品把赌注押在另一边：**过程可验证比结论更有价值**。

具体体现在四个设计决定上：

1. **规则层与 Agent 层物理隔离。** 所有价格口径、形态分类、研究优先级路由都在 `app/engine/` 里，
   这个目录**不 import 任何 LLM**，结果完全可复现、可单测。Agent 只负责语义判断
   （这条新闻在说什么、和公司有没有关系），不负责算数。
2. **证据台账（Evidence Ledger）。** 每一条事实进入系统时都会登记为 `E<n>`，
   带来源分级、发布时间、原始出处。结论只持有证据 ID，不持有文本。
   页面上每个 `E<n>` 都可点击反查原文——这条约束由 `test_main_path.py` 强制：
   引用了台账里不存在的 ID，测试直接失败。
3. **证据强度由规则算，不由模型自评。** 模型的"置信度"本质是文本流畅度的副产品。
   `app/engine/verdict.py` 改为度量**证据链的完整度**：事件是否确认、公司暴露是否确认、
   作用机制是否直接、是否有未解决的反向证据、方向与期限各自有没有依据。
4. **展示约束层。** 证据不足时，即便模型给出了方向和期限，产品也不显示它们，
   只显示"暂无法可靠判断"并说明原因。判断和展示是两件事。

## 四、AI 在产品中的角色

AI 在这个产品里**不是回答者，是研究员**。边界划得很清楚：

**AI 负责（语义判断）**
- 从检索到的资讯里归纳候选驱动因素，并判断它属于市场 / 行业 / 公司哪一层；
- 判断一条新闻与目标公司之间是否存在真实的作用机制；
- 构建基本面传导链，识别抵消因素、放大因素与关键未知；
- 判断影响方向（对经营是正面还是负面）与影响期限（一次性 / 阶段性 / 结构性）；
- 行业识别的第三档兜底（前两档失败时才启用，且结果标记为弱证据）。

**AI 不负责（确定性计算）**
- 任何价格、涨跌幅、集中度、一致性、路径效率的计算；
- 交易日映射与窗口解析；
- 来源分级、事件聚类、独立信源计数；
- 驱动因素状态判定（支持 / 部分支持 / 证据不足）；
- 证据强度评估与展示约束；
- 合规护栏。

**没有 LLM 密钥时**，第二、三阶段会自动切换到内置的确定性启发式推理层
（`app/agent/reasoner.py`，基于关键词词表）。它比 LLM 弱得多，
产品会在页面上明说这一点，而不是假装成完整能力。

模型输出还要过一道校验（`app/agent/llm_reasoner.py`）：
枚举值不合法就回退、引用了不存在的证据 ID 就丢弃、
声称"已确认公司暴露"却给不出有效证据 ID 就强制降级为"无法确认"。

## 五、数据来源

| 层 | 真实数据源 | 用途 | 状态 |
| --- | --- | --- | --- |
| 行情 | 扶摇金融数据 API | 日 K、指数行情、成分股、标的检索、交易日历 | 已实现，需 `FUYAO_API_KEY` |
| 异动线索 | 扶摇 `anomaly-analysis-stock` | 个股异动原因，**仅作检索线索** | 已实现，登记为 T4 未证实 |
| 证据 | iFinD MCP | 资讯、公告、研报 | 接口已预留，未接入实测 |
| 证据（降级） | `fixtures/evidence/events.json` | 内置构造证据集 | 默认启用 |
| 行情（降级） | `fixtures/market/` | 内置构造行情 | 默认启用 |
| 推理 | OpenAI 兼容接口 | 第二、三阶段语义判断 | 已实现，需 `LLM_API_KEY` |

### 关于扶摇的两个调研结论（直接影响了架构）

1. **扶摇的 `/api/news/events/search` 标注为"该能力暂未开放外部接入"。**
   这意味着第二阶段所需的新闻 / 政策 / 公告证据**拿不到**。
   产品因此把 `EvidenceProvider` 做成独立可插拔协议，默认走构造证据集，
   并预留 iFinD MCP 实现。这不是偷懒，是这一层数据源本身不可用。
2. **扶摇的个股异动原因只有当日数据，且是第三方解读。**
   它不能当结论依据，只能当"往哪个方向检索"的提示。
   产品把它登记为 T4_UNVERIFIED，进入线索池，页面上单独一栏展示并注明
   "不作为结论依据"。

### 来源分级

| 级别 | 含义 | 能否支撑结论 |
| --- | --- | --- |
| T1 | 原始权威（交易所、主管部门、公司公告、年报） | 能 |
| T2 | 专业财经媒体 | 能 |
| T3 | 一般媒体 | 能，但会拉低证据强度 |
| T4 | 未证实（社交平台、网传、第三方异动解读） | **不能**，只作检索线索 |

同一份原文被十家媒体转载，独立信源仍然计为 1 个
（`app/engine/source_tier.py` 的 `origin_key` 去重 + 3-gram 聚类）。

## 六、已知边界与未做的事

诚实清单。以下每一条都是明确知道、且有意没做的。

### 数据边界
- **证据层跑在构造数据上。** iFinD MCP 未接入实测，扶摇证据接口未对外开放。
  构造证据集是我按真实场景手写的，刻意埋了三个陷阱用于验证系统行为：
  一条政策的多家转载（验证独立信源去重）、一条收盘后发布的新闻（验证时间检验）、
  一条 T4 网传消息（验证不可支撑结论）。
- **没有分钟级数据。** 所以产品不做盘中因果推断——它只会说"当日变化主要发生在某个阶段"，
  不会说"14:30 的这条新闻导致了之后的下跌"。
- **没有资金流向、龙虎榜、股东户数、融券数据。** 因此"交易/关注度"类驱动因素识别能力很弱。
- **行业识别依赖成分股反向映射**，首次运行需要遍历指数成分股（有调用预算上限，结果落盘缓存 72 小时）。
  两档都失败时才用 LLM 兜底，且结果标记为弱证据。

### 能力边界
- **不做确定性股价预测、收益承诺、买卖建议、目标价。** 这是产品定位，不是能力不足。
  最后一道护栏（`app/engine/guardrails.py`）会正则扫描所有自由文本，
  命中即整句替换——因为提示词约束会被模型偶尔违反，而用户看到的是最终页面。
- **不做百分比归因。** 不会说"市场贡献 40%、行业贡献 35%、公司贡献 25%"。
  三层对比只用于决定研究优先级，产品在页面上明确声明了这一点。
- **不合并多个驱动因素的方向做加权投票。** 方向冲突时就说"正负影响并存"，
  并请用户分别看每个因素的独立评估。
- **只支持 A 股，只支持三个窗口**（今日 / 最近 3 个交易日 / 最近 5 个交易日）。
- **窗口必须由用户指定。** 窗口口径直接决定结论，产品不替用户默认选一个。

### 验证边界
- **Docker 镜像未在本机构建过。** 开发机上没有 Docker，所以 `Dockerfile` 是按
  HF Spaces 的 Docker SDK 约定写的（非 root 用户、`app_port: 7860`、缓存目录预先 chown），
  但没有跑过 `docker build`。代替验证的方式是：从 `git archive` 导出一份干净检出，
  在全新虚拟环境里只装 `requirements.txt`，确认服务能启动、接口能返回、138 项测试全过。
  这能证明依赖清单完整、不依赖任何本地残留文件，但不能替代一次真实的镜像构建。

### 未做的事
- 用户持仓、个性化推荐、自选股监控、推送提醒；
- 多轮追问与对话式澄清（当前是单轮提问 → 单份 Brief）；
- 历史 Brief 的持久化与回溯对比；
- 移动端的深度适配（做了响应式断点，但没有按移动端重新设计信息层级）；
- 演示视频。

## 七、目录结构

```
app/
  contracts.py        数据契约：Fetched 包裹、Evidence、来源分级、各类枚举
  schemas.py          Brief 输出结构
  config.py           配置与 auto 降级解析
  ledger.py           证据台账：登记、聚类、独立信源计数、悬空 ID 过滤
  trace.py            研究轨迹记录与脱敏
  engine/             确定性规则层（不 import LLM）
    resolver.py         股票识别 + 交易日映射 + 非交易日回退
    price_profile.py    当日六项指标
    patterns.py         区间形态：集中度 / 一致性 / 路径效率 / 回撤 / 分类
    industry.py         行业识别三档：结构化 → 成分股反向映射 → LLM 兜底
    priority.py         市场/行业/个股三层对比 + 研究优先级路由
    source_tier.py      来源分级、事件聚类、独立信源计数
    verdict.py          证据强度计算 + 结构性期限门槛 + 展示约束层
    guardrails.py       合规护栏
    presenter.py        数值展示（唯一把 None 渲染成"数据不可用"的地方）
  agent/              语义推理层
    evidence_collect.py 证据窗口构建与检索
    reasoner.py         确定性启发式推理（无 LLM 时的降级实现）
    llm_reasoner.py     LLM 推理 + 输出校验 + 逐调用回退
    prompts.py          提示词
    validation.py       时间 / 横截面 / 特异性 / 机制 四项验证
    drivers.py          驱动因素状态判定
  providers/          数据源协议与实现（fuyao / ifind / mock / llm）
  orchestrator.py     三阶段编排
  main.py             FastAPI 接口（含 SSE）
  static/             无构建前端（原生 HTML/CSS/JS）
fixtures/             构造数据集
scripts/build_fixtures.py  构造数据生成器（确定性，可复现）
tests/                138 项测试
docs/AI_USAGE.md      AI 使用与验证记录
docs/TESTING.md       测试说明
```

## 八、接口

| 接口 | 说明 |
| --- | --- |
| `GET /api/health` | 健康检查 |
| `GET /api/config` | 当前数据源、降级状态、可选窗口、进度步骤、阈值 |
| `POST /api/research` | 一次性返回完整 Brief |
| `GET /api/research/stream` | SSE 流式返回研究进度（`start` → `step`* → `brief` → `done`） |

两条研究接口都支持 `faults` 参数注入接口失败，用于现场演示"数据拿不到时产品如何显式暴露缺口"：

```bash
curl -X POST localhost:8000/api/research \
  -H 'Content-Type: application/json' \
  -d '{"query":"宁德时代","window":"d5","faults":["index_daily_bars"]}'
```

页面也可以直接用链接直达，方便分享：
`http://127.0.0.1:8000/?q=宁德时代最近5个交易日怎么一直跌&w=d5`
