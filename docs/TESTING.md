## 一、主链路

验证的是：用户提一个自然语言问题，产品能走完三个阶段，产出结构完整、可反查的 Brief。

- 五个区域都有内容，三个场景（行业+公司叠加 / 市场同步 / 公司特有）各自路由到正确的研究优先级；
- **所有被引用的证据 ID 必须真实存在于证据台账**。这是产品最核心的约束：
  结论只持有 ID，引用了台账里没有的 ID（模型幻觉出来的 `E99`）测试直接失败；
- 页面展示的区间涨跌必须能由页面展示的 K 线自己算出来——不允许存在两套数；
- 一份原文被多家媒体转载时，独立信源计为 1（用 `origin_key` 去重而不是看标题）；
- 研究轨迹记录了每一次工具调用，且**不包含任何密钥**；
- HTTP 与 SSE 两条接口都能拿到结果，SSE 的事件序列是 `start` → `step`* → `brief` → `done`，
  且进度事件必须在结果之前推送。

## 二、数据缺失与接口失败

这一组测试的共同断言是同一句话：**失败必须可见**。
产品可以少说、可以说不知道，但不允许在数据缺失时静默给出一个看起来完全正常的结论。

用 `faults` 参数注入故障，逐个验证：

| 注入的故障 | 期望行为 |
| --- | --- |
| `index_daily_bars` | 三层对比显示"数据不可用"，研究优先级降级为公司特有因素优先，缺口登记进未解决问题 |
| `search_events` | **不产出任何驱动因素**，总体判断标记为无法形成；但第一阶段行情计算不受影响 |
| `search_events:company` | 只丢公司范围的因素，其余照常，缺口照登记 |
| `daily_bars` | 直接报错，而不是渲染一个空壳页面 |
| `trading_days` | 直接报错，**不退回"按自然日算"**——那会悄悄改变窗口口径 |

其中一条专门盯着"缺失不能被 0 冒充"：
指数数据缺失时，"个股相对行业"必须是 `None` 并显示"数据不可用"，
而不是算成 `0.00pct`。

错误路径也有测试：未知标的返回 422 且带 `code`；
未指定窗口返回 `need_window` 且给出可操作提示（窗口口径直接决定结论，产品不替用户默认选一个）；
SSE 出错时发 `error` 事件并正常收 `done`，而不是让连接悬挂导致前端一直转圈。

## 三、合规边界

护栏测试分两层，**两层都过才算这条边界成立**：

**第一层：护栏本身拦得住。**
买卖建议（"建议买入并长期持有"、"给予买入评级，目标价 260 元"、"逢低吸纳"）
和确定性预测（"股价将在下周反弹至 250 元"、"必然上涨，预计收益率可达 30%"、"稳赚不赔"）
逐条验证被整句替换——半截的买卖建议读起来仍然像建议，所以不做部分遮蔽。

同时有一条**反向测试**：护栏不能误伤正常的研究表述。
"若该因素持续，相关业务的经营条件面临压力""现有证据不足以判断影响期限"
这类句子必须原样通过，否则护栏会逼着产品说不清话。

**第二层：真实输出里本来就没有违规表述。**
把四个场景的 Brief 里所有会出现在页面上的自由文本（约 88 个字段）全部扫一遍，
必须零命中。

此外还验证了几条产品定位层面的边界：

- 证据不足时，**即便模型给出了方向和期限，产品也不显示它们**，只显示"暂无法可靠判断"并说明原因；
- T4 未证实来源（网传消息）永远进不了第三阶段影响评估；
- 市场级因素不会被包装成公司暴露（见 `docs/AI_USAGE.md` 第 1 条）；
- 结构性影响期限必须有正式披露级别的暴露证据支撑，光靠媒体报道推不出来；
- 不做百分比归因——三层对比的免责声明必须在，且全文不出现"贡献 X%"式表述；
- 传导链判断的是**公司经营**，不是股价：链条里不允许出现"股价"；
- 条件句（"若…"）必须标记为推断，否则读者会把假设当结论。

## 四、极端与边界场景

单个公式的边界在单元测试里逐条覆盖（涨跌停一字板、停牌、盘中、前收盘缺失、
历史不足、基准成交额为零）。这一组关心的是**整条链路在边界上的行为**：

- 研究日期落在非交易日时自动回退，且**必须把回退说出来**——否则用户会以为看的是今天的数据；
- 收盘后发布的消息解释不了收盘前已经发生的价格变化，时间检验必须判不吻合，
  该因素不得进入影响评估；
- 查询里只有代码、夹杂噪声词、带语气词的各种写法都能正确识别标的；空查询干净报错；
- 3 日与 5 日窗口必须算出不同结果（窗口口径会改变结论）；
- 3 个交易日不报最大回撤（样本太少，这个指标没有意义）；
- 今日窗口只给当日六项指标，不混进区间指标；
- 个股相对行业仍有未被解释的额外变化时，必须留成未解决问题，而不是塞给某个驱动因素；
- 年报不当驱动因素，但也不能被整个丢掉——它必须出现在公司暴露证据里；
- 三个场景的"未解决问题"区都不允许是空的。
