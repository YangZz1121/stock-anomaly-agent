# AI 使用与验证记录

> 对应交付要求：说明使用了哪些 AI 工具、AI 参与哪些环节、候选人修正了哪些错误或不合理结果。  
> 本文同时作为对话行为复盘：用真实决策记录，说明候选人在规划、分析、逻辑、严谨、用户友好、数据链路、技术栈上的判断，而不是「AI 写了代码、人点了确认」。

---

## 一、使用了哪些 AI 工具

| 工具 | 角色 | 候选人如何使用 |
| --- | --- | --- |
| **Cursor（对话式编码助手）** | 开发期主力 | 按候选人已写好的产品规划落地架构、生成代码与测试、对照开源项目检索口径、本地联调与发版。候选人给目标、约束和验收标准，AI 执行。 |
| **Cursor 内置文档检索** | 数据源调研 | 通读扶摇 API 文档（`llms-full.txt`），确认哪些接口真能用、哪些标注「暂未开放」。调研结论直接改架构，而不是先写死再返工。 |
| **产品运行时 LLM（OpenAI 兼容，实测 glm-5）** | 研究 Agent | 只做语义判断：意图路由、候选驱动因素、机制与传导。不算行情、不评证据强度、不写买卖建议。无密钥时降级为确定性启发式，并在页面如实声明。 |
| **未使用** | — | 未把外部搜索结果当事实；未让模型自行决定产品定位、合规边界或展示规则。 |

原则：**AI 是研究员和实现助手，不是产品决策者。** 规则层与 Agent 层物理隔离——`app/engine/` 不 import 任何 LLM。

## 二、AI 参与了哪些环节

### 2.1 候选人主导（AI 只负责执行）

这些判断在对话里先于代码出现，写进《个股异动研究 Agent 产品规划 V1》（29 节）后，才交给 AI 实现：

| 环节 | 候选人的决策 |
| --- | --- |
| 问题定义 | 不做「会解释涨跌的聊天机器人」，做「可验证的个股事件研究 Brief」。 |
| 用户与非目标 | 面向能自行判断的 A 股主动投资者；不做盯盘、持仓、目标价、买卖建议。 |
| 三阶段框架 | 发生了什么 → 为什么发生 → 对公司意味着什么；六问留在系统内部，前端不做成六个 Tab。 |
| 规则 / Agent 边界 | 行情、窗口、来源分级、展示约束由规则算；模型只做语义。 |
| 数据策略 | Provider 可插拔；扶摇新闻接口未开放则证据层走构造集并预留 iFinD；异动解读只作 T4 线索。 |
| 技术栈 | 纯 Python + FastAPI + 无构建前端（开发机无 Node / Docker / brew）；部署从 HF Spaces 转到可跑服务端的方案。 |
| 合规 | 事实 / 推断 / 未知必须分开；数据缺失不得静默补全「正常结论」。 |

### 2.2 AI 大量参与（候选人验收）

- 主链路代码、测试初稿、README 初稿、数据契约（`Fetched` / `Evidence` / 来源分级）。
- 对照 TradingAgents-astock、tick-stock-panel、microsoft/qlib、a-stock-data 的**判定口径**移植（涨跌停、偏离值闸门、β 残差、reason tags），而不是整仓引入重依赖。
- Agent 流水线脚手架：规划器、工作记忆、工具调用、人机协作、20 轮上下文。

### 2.3 候选人明确禁止 AI 越权的环节

- 百分比归因、方向加权投票、用年报解释当天涨跌、把市场因素包装成公司暴露。
- 窗口未指定时替用户默认一个窗口（窗口口径会改变结论）。
- 把故障演练、调试文案、模型名称暴露给终端投资者。

## 三、从对话看产品设计能力

以下均来自开发当日的真实对话，不是事后包装。每条都对应「AI 给出了能跑的结果 → 候选人判定不合理 → 改产品规则」。

### 3.1 规划：先定边界，再让 AI 动手

- 先让 AI **只读题目**，再提交自己写的规划文档，要求「基于这两个文档构建」，而不是让模型发明产品。
- 扶摇调研出两个架构级结论后，才批准实现：新闻检索接口未对外开放；个股异动原因只有当日、且是第三方解读。因此证据层必须可插拔，异动接口只能进线索池。
- 发现「行业分析节点总报错」后，不是让 AI 加重试，而是改流程：**先判定公司所属行业，再定向取数**；行业列表预置，避免每次扫全市场。
- 主动要求把流水线升级为 Agent：人机协作、当前窗口最多 20 轮、规划器改为 Function Calling。缺模块先盘点，再改，而不是堆提示词。

**能力点**：把 24 小时题目拆成可交付主链路，并在数据不可用时改架构，而不是假装数据已通。

### 3.2 分析：把「同时发生」和「因果关系」拆开

- 要求对照口碑较好的开源项目检查异动逻辑，并只复用口径、不复用「多分析师辩论买卖」——后者没有证据台账，会用流畅文本补断环。
- 追问「待确认的定义是什么？为什么不能只展示已确认的影响因子？」——把「事件存在」和「方向可展示」拆开。
- 追问「证据链不完整，是不是需要论据推导链路？开源项目做到了吗？」——确认开源项目停在检测或残差，推导必须自己做：`事件 → 暴露 → 机制 → 方向 → 期限`，缺环不得下结论。
- 要求说清「驱动因素」和「基本面影响」两套逻辑：前者解释这次价格，后者判断对公司经营的方向与期限。证据够解释涨跌，不等于已确认利好或利空。

**能力点**：分析框架先于展示；星级、标签、章节都映射到已有验证状态，不另起一套不可解释的分数。

### 3.3 逻辑性：先路由，再研究

候选人否定「一上来就跑完整研究报告」的 chatbot，重写意图路由：

1. 先确认必要参数（公司 / 股票）；名词要做泛化映射。
2. 简单 query 只快速查行情，不走完整 Agent。
3. 复杂 query 拆任务；多公司必须分开，禁止混写。
4. 无意义输入不调模型、不调 MCP，直接固定文案。
5. 用户明确要完整报告时，先给等待预期（「预计 x 分钟」），再展示任务链路。
6. 闲聊可调模型；问到底层模型时固定回复「基于您的提问，我会挑选最合适的模型」，避免把运行时模型当卖点。
7. 多轮对话取**最新**公司主题；语义要求合并时可并行分析多家，而不是死守唯一值。

公司识别被打回三次：先改「模型抽取 + 公司名/简称库 + 相似度 80%」；查不出时追问「为什么查不出来」；再要求核对库是否覆盖 A 股、港股全量，并用扶摇 / iFinD 更新，而不是继续调提示词。

**能力点**：把自然语言入口设计成状态机，而不是「有问题就研究」。

### 3.4 严谨性：能跑不等于正确

候选人多次在「页面已经出结果」之后否决：

| 候选人的判定 | 被否决的 AI 行为 |
| --- | --- |
| 本地链接是真实行情还是构造数据？ | 禁止用「能打开」代替数据源声明。 |
| 比例指标被染成红色 | A 股红 = 涨；无方向比例不能套涨跌色。根因是 `Measure.unit` 从未填写。 |
| 「不选时从问题里识别」 | 暗示产品会替用户选窗口，删除。 |
| 故障演练给终端用户看 | 目标用户是个人投研，不是评审调试台，删除。 |
| 影响度五档能否直接划分？ | AI 被要求先回答「现有逻辑够不够」。解释度可映射；影响度只能模拟，且必须标注，禁止伪装成涨跌贡献。 |
| 验证门槛 | 改为「≥3 项验证为支持，才算识别到有效因素」，避免单项巧合过关。 |
| 无支持因素时仍展示基本面含义 | 前端短路：没有可支持异动的因素，不展示第三阶段。 |
| 测试失败先改实现 | 交易日窗口用例是 AI 手算错日期；候选人侧的验证原则是：测试失败先核对期望值，不迎合测试改产品。 |

**能力点**：把「看起来完整」当成最高风险，而不是交付完成的信号。

### 3.5 用户友好性：按投资者阅读资讯的方式改信息结构

连续两轮改报告，都是候选人用真实阅读体验打回：

**第一轮**：按卖方分析师标准提高专业性——结果仍然太重。  
**第二轮**给出可执行的信息架构：

1. 遍历全部分析维度（系统侧不能偷懒）；
2. **只展示**与异动直接相关或间接影响的信息；无法判定、不指向本公司的不展示；
3. 每个模块固定结构：一句洞察 → 一段最重要信息 → 末尾列其他信息；
4. 检查重复项、无效项、语义不明项。

驱动因素区的打回更具体：第三部分不能是新闻堆砌。先给利好 / 利空判断，再短观点，不要完整信息堆叠。

交互上同样按终端习惯改，而不是按「Agent 演示」改：

- 产品必须是**面向终端投资者的 chatbot 信息流**，不是资讯平台；
- 删除「左侧菜单展开 → 新建对话」；「新建对话」放到右上角、证据链左侧，降低路径；
- 闲聊、无意义输入、缺参数都要有人话，而不是报错栈或空白进度条。

**能力点**：专业性来自取舍，不是来自信息更全。

### 3.6 数据链路：先测通，再决定下一步

候选人没有把「接了 API」当成「链路可用」，而是拿自检输出逐项对：

```
行情层：交易日历 / 标的检索 / 日 K / 市场指数 / 行业指数  → 通（扶摇）
异动原因：当日无记录 → 降级（允许，只作线索）
证据层：MCP 失败「Request URL is missing http:// or https://」 → 不通
```

据此拆出真实缺口：缺的是证据层协议前缀与可用性，不是「再写一层总结」。后续要求：

- 行业节点改为「公司 → 预置行业清单 → 只拉该行业日 K / 成分股 / 资讯」；
- 固定数据做成缓存列表（交易日历、标的、成分股、日 K），减少重复计算；
- 公司名库更新为全量，优先走扶摇 / iFinD，而不是手维护几条别名。

数据契约上，候选人坚持：结论只持有证据 ID；页面每个 `E<n>` 必须能点回原文；缺失显示「数据不可用」，禁止用 `0` 冒充。

**能力点**：链路设计是「取数 → 登记 → 验证 → 展示约束」，不是「模型读网后写一段话」。

### 3.7 技术栈：先问缺什么，再升级，再验证耗时

- 先问「现在是不是按 Agent 架构建的？缺哪些模块？」再批准升级，而不是一上来重写。
- 升级约束由候选人指定：人机协作、20 轮上下文、规划器 FC；非法动作回退启发式，保证无密钥时测试与主链路不变。
- 部署上追问「HF Spaces 是否必须 Docker？Static 行不行？」——核实后放弃 Spaces：免费档只剩 Static，没有服务端，且 secrets 会暴露到客户端。
- 发版前反复要求：自测稳定性 / 可用性 / 各环节耗时；覆盖简单、复杂、未设计过的兜底场景，单独成清单，方便后续优化。
- 性能要求具体：识别耗时问题，固定数据缓存，避免重复计算。

**能力点**：技术选型服从约束（无 Node、无 Docker、密钥不能进前端），Agent 能力服从可回退，而不是追最新框架。

## 四、候选人修正了哪些错误或不合理结果

这一节是验证记录的核心。下列条目都是 **AI 已经写出能运行的结果，但行为错误或产品不合理**，由候选人审阅、跑通或对照截图后纠正。

### A. 产品判断错误（对话中当场打回）

#### A1. 把「待确认」当成第三类影响因子

- **AI 结果**：驱动因素卡片出现「待确认」，和利好 / 利空并列。
- **为什么不合理**：待确认确认的是**方向还没过展示门槛**，不是事件没发生。政策可以已经见报，仍然不能写成利好或利空。投资者会把它读成已经成立的因子。
- **候选人修正**：第三部分只保留方向已确认的因子（利好 / 利空 / 利弊并存；部分充分时写「倾向」）。待确认不进影响因子，只进「待观察」。无已确认因子时，不展示基本面含义。

#### A2. 第三部分变成新闻列表

- **AI 结果**：驱动因素标题和正文都是新闻原文，用户要自己猜利好还是利空。
- **为什么不合理**：研报应先定性、再给短观点；新闻原文只作证据，不是结论。
- **候选人修正**：卡片改为「极性 → 短标题 → 解释度（可映射） / 影响度（仅模拟且必须标明）→ 一句观点 + 证据编号」。并追问影响度五档是否真能划分——AI 被要求承认：解释度够，影响度不够，不能伪装成贡献度。

#### A3. 报告信息过载

- **AI 结果**：按「专业研报」加章节后，阅读成本更高。
- **为什么不合理**：专业投资者读资讯要的是相关信息，不是维度展览。
- **候选人修正**：系统侧仍遍历全部维度；展示侧只留直接 / 间接相关项；模块统一为「洞察 + 一段最重要信息 + 其他信息」；删除重复、无效、语义不明项。

#### A4. Chatbot 没有入口逻辑

- **AI 结果**：任意输入都试图走完整研究。
- **为什么不合理**：缺公司名、无意义闲聊、简单行情问询和完整研报，成本与预期完全不同。
- **候选人修正**：必要参数 → 简单 / 复杂 / 无意义 / 闲聊 / 完整报告 五条路由；多轮取最新公司主题；完整报告先给等待文案。

#### A5. 公司识别「像做了，实际查不出」

- **AI 结果**：号称有名词映射，真实 query 仍缺上市公司参数。
- **为什么不合理**：规则抽取覆盖不了简称、别称、上下文指代。
- **候选人修正**：模型抽取 + 公司名/简称库 + 80% 检索；再要求核对 A 股 / 港股全量并用 API 更新，而不是继续改正则。

#### A6. 行业分析反复失败

- **AI 结果**：行业节点每次检索全量行业树，稳定报错 / 超时。
- **为什么不合理**：行业首先是数据问题。不知道公司属于哪一行，就不应开放检索。
- **候选人修正**：预置一级行业清单，先判定再定向取数；常见股票走种子表，零次行情调用。

#### A7. 把调试能力做成给用户的功能

- **AI 结果**：前端保留故障演练、「不选时从问题里识别」等内部语义。
- **为什么不合理**：目标用户是个人投资者，不是评测员。
- **候选人修正**：删除故障演练与误导文案；新建对话改到证据链左侧，去掉左侧菜单展开路径。

#### A8. 部署选型照抄文档默认值

- **AI 结果**：按 HF Spaces Docker SDK 写 Dockerfile。
- **候选人核实后修正**：当前免费 Spaces 只剩 Static，跑不了 FastAPI，且 secrets 会进前端。放弃 Spaces，改为可跑服务端的部署，并在 README 写明原因，避免以后重复踩。

### B. 研究正确性错误（能跑，但结论是假的）

#### B1. 市场因素被伪造出「公司暴露」证据链（严重）

- **现象**：在「隔夜外围主要股指普遍收跌」下，产品写「公司暴露：正式披露确认——依据海外客户长期供货协议」。
- **根因**：相关性用 2-gram，两段文本都含「海外」。
- **修正**：市场 / 宏观因素不再走公司暴露确认；其余类别重合门槛提高到 ≥2 个实词。
- **回归**：`test_compliance.py::test_market_wide_factors_are_not_dressed_up_as_company_exposure`

#### B2. 年报被当成「今天下跌的原因」

- **现象**：年度报告出现在驱动因素列表。
- **根因**：AI 把正式披露都当成事件。年报是慢变量，只能证明业务暴露，不能解释某一天的价格。
- **修正**：仅含 FILING 的聚类不进候选驱动因素，但必须保留为暴露证据（不能整段丢掉）。
- **回归**：`test_extremes.py::test_background_filings_are_not_proposed_as_drivers`

#### B3. 检索召回无关行业事件

- **现象**：研究宁德时代时出现「白酒子板块承压」「乳制品板块午后走弱」。
- **根因**：检索词是「行业 政策 供需」这类泛用词。
- **修正**：公司范围必须命中股票名，行业范围必须命中行业名或股票名。

#### B4. 「长期供货框架协议」被打成结构性影响

- **根因**：词表把「长期」直接当作结构性关键词。商业文本里「长期协议」达不到「改变竞争位置 / 产能 / 商业模式」的门槛。
- **修正**：移出结构性词表，并在代码里写明理由。

#### B5. 护栏漏掉真实预测句式

- **现象**：「股价将在下周反弹至 250 元」没被拦下。
- **根因**：正则要求「将」与动词紧挨，中间不能插时间状语。
- **修正**：中间最多 12 字，但不许跨句；并补反向测试，避免误伤「若该因素持续，经营条件面临压力」这类研究表述。

#### B6. 测试期望值本身算错

- **现象**：3 日 / 5 日交易日窗口测试失败。
- **排查**：2026-09-22 是交易日，窗口应为 `[09-18, 09-21, 09-22]`。AI 手算错日期。
- **修正**：改期望值并加注释。**不改实现去迎合测试。**

#### B7. 中英 / 中俄混杂导致匹配失效

- **现象**：文案出现 `已由正式披露confirm`、`白酒индустрия承压`；中文正面词表混入 `framework`，导致中文匹配全失效。
- **修正**：全部清除，并意识到这不是文案问题，是规则层失效。

#### B8. 比例指标套用涨跌配色

- **现象**：「路径效率 100%」显示为红色。
- **根因**：`Measure.unit` 从未被填，前端无法区分有方向涨跌和无方向比例。
- **修正**：补齐 `pct` / `pct_points` / `share` / `ratio` 等单位；只对带方向的单位套红绿色。同时补上赛题要求的「来源、时点、单位、口径」。

## 五、验证手段（如何发现上述问题）

发现问题依靠可重复手段，而不是「把代码读一遍」：

1. **端到端跑构造场景，逐字读 Brief**  
   B1–B4 都是这样发现的：进程不报错，但「驱动因素：公司年度报告」读出来就是错的。
2. **对照真实页面 / 截图做信息架构评审**  
   A1–A3、B8 只能靠人眼：新闻堆砌、待确认并列、红色 100% 比例。
3. **数据源自检脚本，逐项看通 / 不通 / 降级**  
   证据层缺 `https://`、异动接口当日无记录，都是自检输出，不是模型「感觉接上了」。
4. **先写自测清单，再跑**  
   覆盖稳定性、可用性、各步耗时；简单 / 复杂 / 多公司 / 缺参 / 无意义 / 闲聊；未设计过的兜底单独建档。
5. **离线回归测试**  
   主链路、数据缺失、合规、极端窗口全部不依赖网络和密钥。构造数据里埋了三个陷阱：政策多转载（独立信源去重）、收盘后新闻（时间检验）、T4 网传（不能支撑结论）。
6. **测试失败时先审期望值**  
   B6 证明：第一反应不能是改产品迎合测试。

## 六、AI 与候选人的职责对照（可对外陈述）

| 问题 | 答案 |
| --- | --- |
| AI 做了什么？ | 按规划生成实现、检索开源口径、写测试初稿、执行重构与发版操作。 |
| AI 不能做什么？ | 不能决定研究什么、展示什么、缺数据时是否编造、以及用户看到的信息层级。 |
| 候选人做了什么？ | 定义用户、非目标、三阶段框架、证据链、展示约束；用真实 query / 截图 / 自检日志打回不合理结果；把纠偏写成规则和测试，而不是一次性改文案。 |
| 如何证明不是「AI 代做」？ | 规划文档先于代码；两次架构级调研改变数据层；十余处「能跑但错误」的纠偏都有对应回归；报告与交互被连续打回，直到符合投资者阅读方式。 |

一句话：

> **规则负责确定性，Agent 负责不确定性；证据决定结论边界，用户保留最终投资决策权。AI 加速实现，不代替产品判断。**
