# AI 使用与验证记录

本文件记录这个项目在**开发过程中**如何使用 AI，以及人工发现并修正了哪些 AI 产出的错误。
（产品**运行时**如何使用 AI，见 README 第四节。）

---

## 一、用了哪些 AI 工具

| 工具 | 用途 |
| --- | --- |
| Cursor（Claude 模型） | 主力编码环境：架构设计、代码生成、测试编写、重构 |
| Cursor 内置文档检索 | 抓取并通读扶摇 API 文档（`llms-full.txt`，约 409KB），确认接口能力边界 |
| 无浏览器搜索 / 无外部检索服务 | 本次开发未使用联网搜索；所有外部事实来自扶摇官方文档原文 |

产品**运行时**的 LLM 调用走 OpenAI 兼容接口（`LLM_BASE_URL` / `LLM_MODEL` 可配），
默认未配置密钥，此时自动降级到内置确定性启发式推理层。

---

## 二、AI 参与了哪些环节

### 大量参与
- **代码生成**：约 10000 行代码（`app/` + `tests/` + `scripts/`）绝大部分由 AI 生成。
- **测试编写**：138 项测试的初稿由 AI 写出，人工逐条审阅断言是否真的在验证有意义的性质。
- **文档撰写**：README 与本文件的初稿。
- **数据契约设计**：`Fetched` 包裹、`Evidence`、来源分级枚举的结构。

### 人工主导，AI 执行
- **产品定位与三阶段研究框架**：来自人工撰写的产品规划文档（29 节），AI 按规划实现。
- **技术栈选择**：人工决定纯 Python + 无构建前端（因为开发机上没有 Node/Docker/brew）。
- **数据源策略**：人工决定"先做可插拔 + 内置 Mock 跑通主链路"。
- **部署目标**：人工决定 Hugging Face Spaces。

### AI 几乎没参与
- **合规边界的划定**：不做预测、不给建议、不做百分比归因，这些是产品定位判断，写进规划后 AI 才照做。

## 三、人工修正了 AI 的哪些错误

这一节是本文件的重点。以下每一条都是 AI 写出了能跑、但**行为是错的**的代码，由人工审阅或运行结果比对后发现。

### 1. 市场因素被伪造出一条公司暴露证据链（严重）

**现象**：在"隔夜外围主要股指普遍收跌"这个市场级驱动因素下，产品显示
"公司暴露：正式披露确认 —— 依据「公司公告：与海外客户签署长期供货框架协议」确认公司相关业务暴露"。

**为什么是错的**：一份关于海外客户供货协议的公司公告，和"全球风险偏好回落"没有任何关系。
它们被关联起来，只是因为 AI 写的相关性匹配用的是 2-gram 重合，而两段文本恰好都含"海外"两个字。
这是产品最不该犯的错误——**凭空生成一条看起来完整的证据链**。

**修正**（`app/agent/reasoner.py`）：
- 市场 / 宏观类因素**不再走公司暴露确认**。风险偏好回落对每一家上市公司都成立，
  它本来就不构成公司特有的业务暴露，机制只能停在"部分成立"。
- 其余类别的暴露匹配把门槛从"重合 ≥1 个词"提高到"重合 ≥2 个词"。
  实测数据支持这个阈值：真实的暴露关系（行业政策 ↔ 公司年报）重合 4 个实词
  （动力、力电、电池、出口），而两处误匹配各自只重合 1 个泛用词（"海外"、"主要"）。

**回归保护**：`tests/test_compliance.py::test_market_wide_factors_are_not_dressed_up_as_company_exposure`

### 2. 公司年报被当成"今天下跌的原因"

**现象**：年度报告出现在驱动因素列表里。

**为什么是错的**：年报是慢变量、是背景信息，它能说明"公司在某业务上有多少暴露"，
但它不是一个**事件**，不能解释某一天的价格变化。

**修正**：`ClusterInfo` 增加 `kinds` 与 `is_background`，只含正式披露（FILING）的聚类
不进入候选驱动因素，但保留为公司暴露证据。启发式与 LLM 两条推理路径都加了这层过滤。

**回归保护**：`tests/test_extremes.py::test_background_filings_are_not_proposed_as_drivers`
——这条测试同时断言年报**没有被整个丢掉**，而是确实出现在暴露证据里。

### 3. 检索召回了完全不相关的行业事件

**现象**：研究宁德时代时，"白酒子板块承压""乳制品板块午后走弱"被当作候选驱动因素。

**为什么是错的**：AI 写的检索词是"行业 政策 供需"这类泛用词，能匹配上任何行业的任何新闻。

**修正**：加入 `required_terms` 实体门槛——公司范围必须命中股票名，
行业范围必须命中行业名或股票名，市场范围不设实体门槛（市场因素本来就是全局的）。

### 4. "长期供货框架协议"被判定为结构性影响

**现象**：一份普通的长期供货协议触发了最高级别的"结构性"影响期限。

**为什么是错的**：AI 把"长期"直接放进了结构性关键词表。但"长期协议""长期客户"
是商业文本里的常见措辞，达不到规划里给结构性影响定的高门槛
（改变公司的竞争位置、产能格局或商业模式）。

**修正**：从结构性词表里移除"长期"，并在代码里写明理由。

### 5. 比例类指标套用了涨跌红绿配色

**现象**：页面上"路径效率 100%""方向一致性 100%""单日集中度 34%"显示为红色。

**为什么是错的**：A 股语境下红色 = 上涨。把一个无方向的比例染成红色，
读者会误读成"涨了 100%"。

**修正**：这一条暴露的其实是更深的问题——`Measure.unit` 字段从头到尾就没被填过，
而赛题要求"必须明确来源、时点、单位及统计口径"。
于是在后端补齐了单位（`pct` / `pct_points` / `pct_abs` / `share` / `ratio`），
前端改为**只对带方向的单位**（`pct`、`pct_points`）套用涨跌配色。

### 6. 护栏漏掉了一类真实存在的预测句式

**现象**：写合规测试时发现，"股价将在下周反弹至 250 元"**没有**被护栏拦下。

**为什么漏了**：AI 写的正则是 `(股价|股票|该股)\s*(将|会|即将)\s*(上涨|下跌|...)`，
要求"将"和动词紧挨着。而真实句子里中间常夹着时间状语。

**修正**：允许中间夹最多 12 个字，但不允许跨句（遇到句号、分号、问号即断）。
同时补了一条反向测试，确认护栏不会误伤正常的研究表述
（`test_guardrails_do_not_touch_legitimate_research_language`）。

### 7. 一条测试的期望值本身是错的

**现象**：`test_three_and_five_day_windows_use_trading_days_not_calendar_days` 失败。

**排查结论**：错的是测试，不是实现。2026-09-22 确实是交易日，
所以以它结尾的 3 日窗口是 `[09-18, 09-21, 09-22]`。
AI 在写测试时手算错了日期。修正了期望值，并加注释说明这个窗口为什么是这三天。

**这条值得单独记一笔**：测试失败时，第一反应不能是改实现去迎合测试。

### 8. 四处中英 / 中俄文混杂的笔误

AI 在生成中文文案时混入了外文词：`"已由正式披露confirm"`、`"白酒индустрия承压"`、
`"经营条件получ改善"`，以及在中文正面词表里混进了英文 `"framework"`
（这一条不只是笔误——它让关键词匹配对中文文本完全失效）。全部已修正。

## 四、验证手段

发现上述问题依靠的不是"读一遍代码"，而是三种可重复的手段：

1. **端到端跑三个构造场景**，逐字读输出的 Brief。
   第 1、2、3、4 条错误都是这么发现的——代码本身没有异常，只有把
   "驱动因素：公司年度报告"这行字读出来，才知道它是错的。
2. **无头浏览器截图**，人眼检查渲染结果。第 5 条错误（配色）只能这么发现。
3. **写测试时对着真实数据核算**。第 6 条是在为护栏补充样例时发现的，
   第 7 条是测试自己失败暴露的。

构造数据集里刻意埋了三个陷阱，用于持续验证系统在这些情形下的行为：
一条政策的多家媒体转载、一条收盘后发布的新闻、一条 T4 网传消息。
它们分别对应独立信源去重、时间检验、来源分级三条规则。
